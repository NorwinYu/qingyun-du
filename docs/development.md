# 青云渡 · 开发文档

> 面向想读代码、改玩法或做二次开发的人。玩法内容见 [玩法指南](gameplay.md)，部署见 [部署说明](deployment.md)。

## 1. 技术栈

| 层 | 选型 | 说明 |
| --- | --- | --- |
| 渲染 | three.js r187 | WebGL2，PCF 阴影、ACES、泛光与调色 |
| 构建 | esbuild 0.28 | 两段构建，最终产出单个 IIFE |
| 语言 | 原生 ES Modules | 无框架、无 TypeScript、无运行时依赖 |
| 界面 | DOM + CSS + Canvas 2D | HUD、背包、地图、小地图均为原生实现 |
| 音频 | WebAudio | 振荡器 / 噪声合成，无音频文件 |
| 人物 | 自研 SDF 拼装 | Worker 生成网格，主线程绑定动作 |
| 测试 | `node:test` + esbuild | 在 Node 中直接加载游戏逻辑做断言 |

运行环境要求：支持 WebGL2 的现代浏览器；构建需要 Node.js 18+。

## 2. 目录与模块职责

```text
src/
├── main.js        主循环、系统编排、输入分发、镜头、交互、天劫、调试接口

├── data.js        静态数据：境界、灵根、物品、任务、丹方、配方、NPC 对话
├── player.js      Input、Player：移动物理、战斗状态、镜头、捏人参数

├── side.js        悬赏、护送、灵田、垂钓、灵环、声望与宗门宝库
├── trial.js       秘境：层数、波次、增益、首领、结算
├── ui.js          HUD、对话框、背包、炼丹/炼器、地图、菜单、Creator
├── world.js       64 m 分块地形、树木/岩石实例、草地、碰撞查询
├── height.js      高度场、群系权重、道路与聚落压平、树木密度

├── build.js       村庄、桥梁、码头等程序化建筑
├── build2.js      城镇、遗迹、火山、仙山、雷劫台等大型结构

├── postfx.js      EffectComposer：泛光、调色、暗角

├── particles.js   通用 GPU 粒子池
├── audio.js       WebAudio 音效与环境声
├── loot.js        装备品质、随机词条、精英词缀
├── collide.js     盒体碰撞世界
├── noise.js       噪声、哈希、插值工具
└── human/         人物：sdf / shapes / build / rig / anim / character / material / worker
```

## 3. 构建

```bash
npm install
npm run build      # 生产构建
npm run dev        # 监听 + 本地服务（默认 :8000）
npm test           # 30 项回归测试
```

### 3.1 两段构建

人物网格在运行时由 SDF 拼装，生成逻辑较重，被放进 Web Worker：

1. `npm run build:worker` 把 `src/human/worker.js` 打成 `build/hworker.wjs`（IIFE）。
2. 主构建用 esbuild 的 `--loader:.wjs=text` 把该文件作为字符串内联进 `dist/game.js`，运行时用 Blob 创建 Worker。

这样最终只需要部署**一个 JS 文件**，也避免了 Worker 的跨域路径问题。代价是仓库里的 `dist/game.js` 约 1.3 MB。

### 3.2 产物

```text
index.html      入口，引用 dist/game.js
dist/game.js    唯一运行产物（自包含 three.js、人物 Worker、全部逻辑）
```

没有资源目录：贴图、模型、音效都在运行时生成。

## 4. 运行时结构

`main.js` 是编排层。启动时依次创建渲染器、纹理与材质、天空、水面、世界、建筑、粒子、玩家、NPC/妖兽、UI，然后进入 `requestAnimationFrame` 主循环。

一帧的大致顺序：

1. 计算 `dt`（命中顿帧、子弹时间会缩放），更新计时与天气。
2. 读取输入；处理攻击、技能、交互、菜单快捷键。
3. 更新玩家物理与动画；触发脚步、挥砍、落地等事件。
4. 更新妖兽 AI、弹道、秘境、悬赏/护送/灵田、天劫。
5. 更新镜头、灯光池（夜间只给最近的灯笼分配点光源）。
6. 更新粒子、特效、水面、天空、雾。
7. 更新 HUD / 小地图，按需构建或卸载地形块。
8. 通过 `PostFX` 合成并输出。

### 4.1 世界流式加载

世界以 **64 m × 64 m** 为块（`world.js` 中的 `CS`）。玩家移动超过阈值时，`loadAround()` 会：

- 为九宫格范围内的新块生成地形、植被实例、建筑与交互点；
- 对超出半径的块做卸载与几何释放；
- 用远景低模与树冠带填补视野边缘，避免“空世界”。

地形高度、群系、道路与聚落压平都由 `height.js` 的纯函数决定，因此同一坐标在任何时候都能得到一致结果。

### 4.2 渲染与画质

`?q=` 与菜单画质对应三档：

| 档位 | 阴影 | 水面反射 | 后处理 | 像素比 |
| --- | --- | --- | --- | --- |
| 0 流畅 | 关 | 关 | 关 | 1 |
| 1 均衡 | 开 | 开 | 泛光 + 调色（4× MSAA） | 1 |
| 2 极致 | 开 | 开 | 同上 | ≤1.5 |

夜晚采用**灯光池**：场景里只保留 7 个点光源，每 0.35 秒重新分配给离玩家最近的灯笼，避免大量动态光源拖慢渲染。

水面使用独立相机渲染反射贴图（512²），并在 `water.js` 里按远近切换网格细节。

## 5. 人物系统

`src/human/` 是一条独立的小管线：

- `sdf.js`：用有符号距离场描述头、身、四肢、衣摆等体块。
- `shapes.js`：按 `look` 参数（性别、发型、衣着、配色、肤色）拼出网格。
- `build.js`：把体块转成三角网格并合并、法线化。
- `worker.js`：在 Worker 中执行上述构建，`postMessage` 传回 TypedArray。
- `rig.js` / `anim.js`：骨骼与程序化动作（走、跑、跳、挥砍、打坐、御剑、游泳、抛竿、耕作）。
- `character.js`：对外的人物对象，负责材质、飘带、武器挂点与动作混合。

同一套参数既用于玩家，也用于 NPC、敌人与创建界面预览。

## 6. 战斗与 AI

- 玩家攻击是带时间窗的状态机：`attackT`、`combo`、`swung` 控制三段连斩的判定与特效事件。
- 命中判定由 `actors.melee()` / `actors.aimTarget()` 完成，支持扇形范围与目标锁定。
- 敌人 AI 由 `state` 驱动（idle / chase / attack / stagger / dead），首领另有阶段与召唤逻辑。
- 精英词缀（狂暴、坚甲、迅捷、嗜血、爆裂、寒霜）在生成时挂到实体上，在移动、受击、死亡分支里读取。
- 前端表现与数值分离：伤害数字、屏幕震动、顿帧、子弹时间都由事件触发，便于单独调手感。

## 7. 数据与存档

- 静态数据集中在 `data.js`，新增物品、任务、丹方通常只需要改这一处。
- `Game` 持有唯一的存档对象 `game.s`，通过 `game.on/emit` 通知 UI。
- 存档键：`qingyun_save_v1`；画质与音量键：`qingyun_opts`。
- 存档为 JSON，包含外观、境界、背包、装备、任务、灵根、声望、灵田、鱼获与灵环纪录。
- 自动保存条件：落地、脱战、非渡劫，每 20 秒一次；关键节点另有手动保存。
- 存档没有迁移层，修改字段结构时需要自行兼容旧档或升版本号。

## 8. 调试接口

### 8.1 URL 参数

| 参数 | 示例 | 作用 |
| --- | --- | --- |
| `q` | `?q=0` | 画质 0/1/2 |
| `auto` | `?auto=1` | 跳过标题直接新开；`auto=2` 读档 |
| `cam` | `?cam=0,20,80,0,4,0` | 自由镜头：相机位置 + 看向点 |
| `hour` | `?hour=21.5` | 设置时辰（配合 `cam`） |

### 8.2 `window.G`

游戏启动后会在控制台暴露调试对象：

| 调用 | 作用 |
| --- | --- |
| `G.tp(x, z, y?)` | 传送玩家到坐标，自动贴地 |
| `G.view(x, y, z, tx, ty, tz, hour?)` | 固定镜头并看向目标，可设时辰 |
| `G.play()` | 取消固定镜头，回到第三人称 |
| `G.cheat(realm)` | 直接设置境界（0 凡人 … 13 金丹初期），补齐功法并回满状态 |
| `G.skip(questId)` | 把某任务之前的主线标记为完成 |
| `G.loot(quality, tier, slot)` | 生成一件随机灵宝 |
| `G.meteor(d)` | 在附近触发一颗流星 |
| `G.rain(k)` | 切换天气 |
| `G.fps` | 当前帧率 |
| `G.scene / G.camera / G.world / G.actors / G.ui ...` | 直接访问各系统 |

截图流程可以完全脚本化：`?auto=1` 开局 → 关对话框 → `G.cheat()`、`G.tp()`、`G.view()` 摆位 → 截图。

## 9. 测试

```bash
npm test
```

`tests/*.test.cjs` 用 esbuild 把 `actors.js` / `world.js` / `trial.js` 等打成 CommonJS，在 Node 中加载（`three` 为外部依赖），对纯逻辑做断言，覆盖：

- 秘境每层敌人不会掉出平台，且能追到玩家；
- 击退落台后的回收；
- 波次推进与清层奖励；
- 万剑归宗落点；
- 灵草生成与地图朝向等。

测试不依赖浏览器，适合在 CI 中运行。改战斗、秘境、生成逻辑时建议先跑一遍。

## 10. 性能备注

- 单帧热点通常在植被实例、阴影和泛光；低端设备优先用 `?q=0`。
- 不要在每帧创建对象或材质；共享材质集中在 `materials.js`。
- 新增点光源前先考虑灯光池；动态光源数量对前向渲染影响很大。
- 粒子使用固定容量的池（`particles.js`），新增特效优先复用发射器。

## 11. 已知技术债

- `main.js` 约 64 KB，仍承担了较多系统编排，适合继续拆分为 `world/`、`combat/`、`quest/` 等模块。
- `build.js` 与 `build2.js` 是两次迭代的产物，存在可合并的建筑辅助函数。
- 没有 TypeScript 与运行时 schema，`data.js` 的结构靠约定。
- 存档没有版本迁移；改字段时需手动兼容。
- 仅支持键鼠，未做移动端 UI 与手柄映射。
- UI 文案为中文硬编码，暂未做多语言。

## 12. 参与开发

1. Fork 并新建分支。
2. 修改后运行 `npm test` 与 `npm run build`。
3. 附上截图（可用 `?cam=` 摆位）与复现步骤。
4. 提交 Pull Request，说明改动范围与验证方式。

如果只是想加内容，通常从 `data.js` 开始：新增物品 / 任务 / 丹方 → 在 `side.js` 或 `main.js` 接交互 → 在 `ui.js` 补展示。
